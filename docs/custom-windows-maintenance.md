# Windows 增强版的合并与升级

当前基线为官方 v3.1.3（`fb00f7f`），在 `custom/windows` 分支维护。
合并前的可回退版本保存在 `custom/v3.1.2-fix6` 标签，对应 `5379201`。
本次构建标识为 `patch=20261029.1 custom=windows-enhanced.7`。

## 合并取舍

- 采用官方拆分后的 `usage` 传输、映射和测试模块，保留批次共享连接、超时、有限重试、8 并发和部分刷新失败提示，不重复保留旧模块。
- 采用官方 API/Relay 配置修复、窗口几何信息保存，以及会话 Token 归属说明。
- Store 启动使用双方一致的直接 AUMID 激活和结果核验，采用官方整理后的格式和测试。
- 主窗口事件先交给官方窗口状态模块处理，再保留原有平台关闭行为；Windows 不调用仅适用于 macOS 的 Dock 接口。
- 五种语言按字段进行三方合并，保留自动切换设置和失败提示；不整份覆盖任一侧文案。
- 保留额度耗尽自动换号、重启桌面、从首页定位原会话、等待输入框就绪、单次发送“继续”及新回合确认。
- 保留 fix6 的候选账号检查：任一额度窗口已耗尽则不能选中；没有候选时不进入切换流程、不重启、不续跑，也不消耗切换冷却时间。
- 保留本地自定义 provider 的 Token 统计过滤及 Windows 构建兼容处理。
- 移除全局删除 `thread-writer-locks/*.lock` 的行为。只停止经过用户、会话、路径和进程身份核验的桌面进程；会话锁交给 Codex 管理，不抢占其他客户端的任务。
- 定制版的启动检查、手动检查和安装入口均不调用官方更新安装器。手动检查显示安装新版增强包的说明，避免官方安装器覆盖定制功能。

## 后续更新

1. 确认工作区干净，为当前可用版本保留标签和完整安装包。
2. `git fetch upstream --tags`，确认最新正式版本的发布说明。
3. 在 `custom/windows` 合入对应正式版本标签，按功能解决冲突；不要全部采用一侧。
4. 检查额度刷新、Store 启动、窗口状态、自动换号和续跑的入口是否仍连接；运行 Rust、前端及 PowerShell 回归。
5. 编译并核对完整安装包，备份本机旧程序后更新；保留旧包用于回退。
6. 将增强版分支和版本标签推送到自己的仓库。官方已关闭的 PR #235 不作为此分支的发布渠道。

本地自动化回归和界面模拟不代表真实额度耗尽后的整条闭环已在所有设备通过。
不通过主动耗尽账号、重复发送继续或强行移除会话锁来验证。

## 增强版 2：停止进程的边界

- 旧实现按 Codex 桌面的整个后代进程树执行停止，可能误关从任务/终端启动的 Studio、IDE 等独立应用。
- 新实现仅选择已确认的桌面路径、同安装目录中的 Codex 组件和官方版本目录的原生服务；路径、父子关系及启动时间必须同时匹配。
- 遇到终端、编辑器、未知路径或未确认身份的进程，不终止它，也不继续沿该分支查杀；独立 Codex CLI 会话保留。
- 进程停止错误向上传递，在停止失败时中止授权切换。自动换号明确禁用手动编辑器重启选项。
- `CODEX_DESKTOP_STOP` 记录选择/保留名单、PID、父 PID、可执行路径、关闭请求及终止动作，不采集命令行或环境变量。
- Rust 回归 426 通过、1 项原有忽略、0 失败；包括 Antigravity Studio/Antigravity 嵌套启动、终端边界、独立 CLI、未知路径和父 PID 复用。
- 排查时编辑器重启与 Opencode 同步均关闭，旧日志没有逐 PID 终止名单，因此无法逐个还原事故中的历史进程归属。未使用真实编辑器执行破坏性的关闭验证。

## 增强版 3：保持 Codex Tools 控制器运行

- 上一次故障日志在停止 Codex 后中断，没有 Tools 的逐 PID 关闭记录；这不能证明 Tools 的退出由显式 TerminateProcess 调用导致。保留证据边界，不把模拟通过当作实机闭环通过。
- 移除 Windows 启动器中按可执行路径强制结束旧 Tools 实例的逻辑，重复启动只由单实例插件唤醒原窗口。
- 进程选择保护当前控制器、同路径的其他 Tools 实例及其界面/辅助分支。用户配置的任意启动路径不能直接成为进程关闭授权。
- 原生关闭函数再次拒绝当前 Tools 及同程序实例，不向它们发送关闭消息或终止调用。
- 在停止任何 Codex 进程前，检查控制器祖先关系和当前 Windows Job 成员；若选中的 Codex 与工具存在依赖，则明确报错并保持应用运行，不尝试重启 Tools 绕过检查。
- 发布更新后通过现有 Explorer 桌面 COM 对象启动 Tools，避免把管理器作为 Codex 命令的普通子进程启动；原程序仍保留备份。正常换号不执行该部署操作。
- 启动日志记录控制器 PID 和 Job 成员，以便区分关闭名单、进程作业和重复启动问题。
- Windows Rust 回归 434 通过、1 项原有忽略、0 失败，增加 8 项控制器保护与依赖检查测试。真实额度耗尽重启没有被主动触发。

## 增强版 4：日志统计与压缩期间的续跑确认

- 新版 paginated 日志在继承记录时会重新分配 envelope ordinal。匹配历史时排除此序号，保留 payload 内的同名字段，避免把父子日志误判为完全不同。
- paginated 子代理日志的 `subagent_history_start_ordinal` 明确标记自身历史边界，优先使用该边界；不要求改写过的上下文与父会话逐条匹配。继承区的累计用量只作基线，独立响应才计数，日志序号缺失或倒退仍保守跳过。
- 账号用量和成本分析共用上述边界，成本缓存版本升级到 13，旧结果自动重建。
- 本机同批 217 份日志对比：未解析日志从 100 份降至 2 份，确认的用量事件从 9316 条增至 12146 条；最近 24 小时有用量的账号从 5 个恢复为 7 个。剩余 2 份的文件名与会话身份冲突，26 条异常累计事件仍不擅自推算。
- 账号列表在 24 小时没有用量时显示标有 7d/30d 的历史值，提示保留三个周期。统计继续按会话创建账号归属，无法据此还原同会话切号后的实际扣费。
- 实际故障中，新回合在发送后数秒内开始，但“继续”消息在上下文压缩结束两分钟后才写入。原生提交已确认时，新回合开始即可确认接收，不再强制等待消息记录。
- 提交后只读观察同一目标输入框的 Send → Stop 变化，连续两次匹配即可确认执行；单纯 Steer/Queue、其他输入框的 Stop、发送前已有的 Stop 都不能证明此次提交成功。观察超时回退到日志核验，不再次发送。
- 不明确的原生提交仍要求日志中的真实“继续”消息与新回合；立即记录的新回合中断或失败继续报错。接收成功不代表整个任务最终完成。
- 回归覆盖继承用量去重、序号与物理行位置差异、压缩延迟写入、提交不明及同输入框 Stop 状态转换。未主动触发真实额度耗尽、账号切换或向用户会话发送测试消息。
- 发布验收：438 项 Rust 测试通过、1 项原有忽略；36 项前端测试、33 项页面及 26 项布局检查通过，ESLint 和生产构建通过。Windows PowerShell 5.1 的 8 个隔离续跑流程与 Send → Stop 检查通过。完整安装包抽取核对 40 个文件；本机界面 7 个账号均显示用量，重复启动保留 Tools 原 PID，23/23 个原有 GUI 进程仍在。

## 增强版 5：标签页中的紧凑输入框

- 2026-10-28 的故障日志显示目标会话及预填“继续”均已找到，但 6 个编辑控件的布局里 Send/Stop 数量均为 0，最终等待发送控件超时；另外两个普通布局会话成功。由此确认失败位于控件定位阶段，不能据此声称曾点击发送。
- 安装版本的静态界面代码将输入框与尾部按钮分别放入自适应 footer；原先仅向上查找 4 层、要求按钮落在文本框横向 ±64 范围且不能高于文字顶端，无法兼容部分标签页/单行布局。
- 现在最多向上查找 12 层，选取最近的、范围受限且只包含当前可见富文本输入框的容器；容器必须包住文本区，横向额外不超过 384、纵向额外不超过 200。只认容器内靠近输入区的明确 Send/Stop/Steer 控件；不扫描应用窗口或嵌入的浏览器文档。
- 根据单行布局允许按钮比文字顶端高 24，或位于文本区右侧的独立控件槽；仍约束容器边界、按钮尺寸和与输入区的距离。
- 不再把同一输入框下不同 Send 按钮按输入框身份合并。候选按钮必须唯一，发送前同时复核输入框和按钮身份；发送后的 Stop 继续按同一输入框确认，不点击停止。
- 只要 helper 没有进入 READY/SUBMIT 授权阶段，超时或退出就明确返回未发送，不再额外等待新回合并输出“已尝试发送”。真正调用发送后仍只核验一次，不重试不明确的提交。
- 隔离测试覆盖第 6 层祖先的兄弟工具栏、横向独立按钮槽、发送/停止切换、普通布局、隐藏标签、第二个富文本框、其他面板、浏览器文档边界及同输入框多个按钮。Rust 增加未授权 helper 失败时明确返回未发送的用例。
- 本次使用故障日志、用户截图、已安装界面静态代码及假元素回归核验；没有操作真实 Codex 会话发送测试消息，也没有强制耗尽额度。修复后同一标签布局的实机续跑结果仍待自然触发确认。
- 发布回归：439 项 Rust 测试通过、1 项原有忽略；Windows PowerShell 5.1 的 9 个隔离流程以及标签页容器、兄弟按钮槽、跨面板排除、按钮身份复核检查通过。生产构建、文本编码/换行和差异凭据扫描通过。
- 安装验收：完整 EXE/MSI 安装包生成成功，MSI 解包核对 40 个运行文件和资源；本机二进制与构建哈希一致，启动日志确认增强版 5。重复启动保留 Tools 原进程，更新前记录的 27/27 个 ChatGPT/Antigravity 相关进程仍在。

## 增强版 6：发送前界面重建时重新等待

- 后续故障发生在找到唯一 Send 并返回 READY 后：编辑控件由 2 个增至 5 个，最后一次复核找不到同一 Send，helper 在 Invoke 前抛出 changed before submission。目标栏或标签页加载可能触发这一变化；现有日志不能证明是目标功能本身直接导致。
- 之前父进程把发出 SUBMIT 授权当成可能已发送，因此把明确发生在调用前的撤销报告为发送结果不明，并额外等待 30 秒。这次将 READY、REVOKED、INVOKING、SUBMITTED 分开处理；调用前异常明确返回 NOT_SUBMITTED。
- READY 现在要求输入框和按钮身份均稳定。最后复核变化时只撤销本次授权，在原有总超时内重新等待就绪，每次 READY 都由父进程重新读取任务状态；父子输入通道在多次握手之间保持打开。
- 一旦进入 Invoke 阶段就不重试；异常仍保留不确定提交的单次核验。没有降低目标会话、草稿、唯一按钮、跨面板排除及 Send → Stop 的原有校验。
- 440 项 Rust 测试通过、1 项原有忽略；Windows PowerShell 5.1 的 10 个隔离流程通过，新增调用前界面变化后重新授权且只调用一次、授权后调用前异常明确未发送、调用异常仍为不确定提交的回归。
- 本次依据故障日志、截图、已安装应用静态代码和隔离用例核验，没有向真实用户会话发送测试消息；目标栏布局的下一次自然恢复结果仍待实机确认。
- 安装验收：完整 EXE/MSI 安装包生成并抽取核对 40 个运行文件和资源；本机应用与本次构建哈希一致，日志确认增强版 6。重复启动保留 Tools 原进程，更新前记录的 25/25 个 ChatGPT/Antigravity 相关进程仍在。

## 增强版 7：停止重复导航并恢复被省略的布局容器

- 新一轮日志中第一条任务自动续跑成功；第二条先短暂识别到 Send，随后输入框仍有“继续”但 Send/Stop 为 0。之后又分发 3 次会话路由和 2 次预填，直到用户手动发送后新回合被检测到。没有 BlockInput/SendKeys 锁输入逻辑，重复打开深链会将应用拉回前台。
- 导航增加前台条件和单向状态：唯一目标一旦被找到便不再重开路由，预填一旦分发或观察到便不再预填。用户切到其他窗口时不导航、不预填、不发送；已调用发送之后仍允许只读核验。首次导航未到达目标时保留有界重试。
- 输入控件查找先走 Control View；若没有找到，改从 Raw View 检查同一输入框的布局祖先，覆盖挂载后被 Control View 省略的装饰容器。两条路径都保留容器尺寸、其他富文本框、按钮距离和 Document/窗口边界，不扩大到整个页面搜索。允许 2 个物理像素的动画/小数边界差异。
- 增加只含计数的定位诊断，区分范围不符、其他输入框、隐藏按钮、名称不匹配、按钮距离不符及是否走了 Raw View，不写入草稿/聊天正文。
- 隔离回归覆盖后台禁止导航/预填、已找到目标后编辑器暂时消失不重开、空草稿不二次填入、Raw View 找回被省略容器及其跨面板/文档边界限制；保留 10 个单次发送/撤销/主页恢复流程。
- 日志只证明按钮定位失败，尚不能证明该次真实布局是因 Control View 省略还是边界排除。本次未操控真实用户会话发送测试消息，按钮定位修复的实机结果仍待自然触发及新增诊断确认。
- 发布验证：440 项 Rust 测试通过、1 项原有忽略；PowerShell 5.1 的生产过滤条件构造、Raw View/后台/单向导航及 10 个隔离流程通过。生产构建和文本检查通过；完整 EXE/MSI 生成，MSI 解包核对 40 个运行文件和资源。本机应用哈希与构建一致，启动日志确认为增强版 7。
